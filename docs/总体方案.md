# EvalLab 总体方案

> 独立的 Agent 离线评测平台，提供从 Trace 采集到回归门禁的完整闭环

## 1. 项目定位

- 核心亮点：
  1. 完整 Trace 采集：两层模型（trace > span），支持嵌套和工具调用链
  2. 多维度自动评分：规则评分 + 工具调用评分 + LLM-as-Judge
  3. 失败归因分层：5 层自动归因（输入理解/规划/工具调用/输出生成/数据环境）
  4. Judge 校准体系：人工抽检对照组，计算 Judge 准确率和归因准确率
  5. 回归门禁：基线对比 + 阈值判断，指标退化时拦截 CI（退出码 1）

- 明确不做：
  - Prompt 管理仓库（中心化版本控制）
  - 生产监控和实时告警
  - 多租户和复杂权限
  - 通用可观测平台对接

## 2. 领域建模

### 核心对象

- **Trace**：一次 Agent 任务执行的完整记录
  - 包含：任务输入/输出、状态、总耗时、总 token
  - 关联：多个 Span

- **Span**：单次工具调用或 LLM 调用
  - 包含：工具名称、输入/输出、耗时、token、错误信息、事件日志
  - 支持：父子嵌套关系
  - 类型：LLM_CALL / TOOL_CALL / RETRIEVAL

- **用例（TestCase）**：评测输入和期望
  - 包含：输入指令、期望输出、期望工具序列、标签、分组
  - 支持：版本管理、启用/禁用

- **评测任务（EvalTask）**：一次批量评测
  - 包含：被测 Agent、用例筛选条件、执行状态、统计指标
  - 关联：多个评测结果、可选基线

- **评测结果（EvalResult）**：单个用例的执行结果
  - 包含：关联 Trace、通过/失败状态、失败原因、失败分层
  - 关联：多个评分记录

- **评分（Score）**：单个维度的评分
  - 类型：RULE（规则）/ TOOL_CORRECTNESS（工具调用）/ LLM_JUDGE（Judge）
  - 包含：评分名称、分数（0-1）、评分理由

- **基线（Baseline）**：历史评测的快照
  - 包含：通过率、平均分、P95 耗时
  - 用于：回归对比

- **人工抽检（ManualReview）**：Judge 和归因的校准数据
  - 包含：人工评分、人工失败分层、对应的 Judge 评分和系统归因
  - 用于：计算准确率

### 状态流转

**评测任务**：
```text
PENDING -> RUNNING -> COMPLETED / FAILED
```

**评测结果**：
```text
PASS / FAIL
```

**Trace**：
```text
SUCCESS / FAILED / TIMEOUT
```

| ORM | MyBatis-Plus | 3.5.9 | 简化 CRUD |
| 数据库 | MySQL | 8.0.40 | 存储 Trace、用例、评测结果 |
| LLM 调用 | Spring AI | 1.1.0 | ChatClient，OpenAI 兼容接口 |

## 4. 数据设计

### 核心表

| 表 | 职责 | 关键约束/索引 |
|---|------|--------------|
| eval_trace | Trace 主记录 | trace_id 唯一，idx(agent_name, created_at) |
| eval_span | Span 记录 | span_id 唯一，idx(trace_id)，idx(parent_span_id)，events 存 JSON |
| eval_testcase | 评测用例 | testcase_id 唯一，idx(group_id)，idx(version) |
| eval_testcase_group | 用例分组（单层） | group_name 唯一 |
| eval_task | 评测任务 | task_id 唯一，idx(agent_name, created_at) |
| eval_result | 评测结果 | result_id 唯一，idx(task_id)，idx(failure_category) |
| eval_score | 评分记录 | idx(result_id)，idx(scorer_type) |
| eval_baseline | 基线快照 | baseline_id 唯一，idx(agent_name) |
| eval_manual_review | 人工抽检 | result_id 唯一 |
| eval_redteam_case | 红队用例（加分项） | case_id 唯一，idx(attack_type) |

### 关键设计

- **Trace 两层模型**：trace > span，events 并入 span JSON，简化查询
- **用例分组单层**：避免树形结构复杂度，group_id 直接关联
- **评分 0-1 量纲**：统一评分标准，便于对比和校准
- **人工抽检字段**：同时存储人工评分/分层和 Judge 评分/系统归因，计算准确率

**请求**：`POST /execute`
```json
{
  "task_id": "uuid",
  "input": "用户指令"
}
```

**响应**：
```json
{
  "trace_id": "uuid",
  "status": "SUCCESS | FAILED | TIMEOUT",
  "output": "Agent 最终输出",
  "total_tokens": 1234,
  "duration_ms": 5678,
  "spans": [
    {
      "span_id": "uuid",
      "parent_span_id": "uuid | null",
      "span_type": "LLM_CALL | TOOL_CALL | RETRIEVAL",
      "tool_name": "工具名 | null",
      "input": "输入参数",
      "output": "输出结果",
      "error": "错误信息 | null",
      "tokens": 100,
      "duration_ms": 234,
      "start_time": "ISO 8601",
      "end_time": "ISO 8601",
      "events": [
        {
          "event_type": "LOG | ERROR | WARNING",
          "message": "日志内容",
          "timestamp": "ISO 8601"
        }
      ]
    }
  ]
}
```

### 故障注入 Agent（验证用）

**请求**：`POST /execute`
```json
{
  "task_id": "uuid",
  "input": "用户指令",
  "fault_injection": {
    "type": "TOOL_ERROR | STEP_MISSING | OUTPUT_FORMAT_ERROR | TIMEOUT | INPUT_MISUNDERSTAND",
    "target_span": "span 编号 | null"
  }
}
```

**故障类型**：
- `TOOL_ERROR`：工具调用返回错误
- `STEP_MISSING`：跳过某个规划步骤
- `OUTPUT_FORMAT_ERROR`：返回不符合格式的输出
- `TIMEOUT`：模拟超时
- `INPUT_MISUNDERSTAND`：故意曲解用户指令

## 6. 接口设计

### Trace 采集

- `POST /api/trace`
  - 入参：完整 Trace JSON（Agent 执行后上报）
  - 出参：trace_id
  - 说明：存储到数据库，解析 span 关系

### 用例管理

- `GET /api/testcase`：查询用例列表（支持分组/标签筛选）
- `POST /api/testcase`：创建用例
- `PUT /api/testcase/{id}`：更新用例
- `DELETE /api/testcase/{id}`：删除用例

### 评测任务

- `POST /api/eval/task`
  - 入参：agent_name、用例筛选条件、baseline_id（可选）
  - 出参：task_id
  - 说明：创建评测任务，异步执行
- `GET /api/eval/task/{id}`：查询任务状态和统计
- `GET /api/eval/task/{id}/results`：查询详细结果

### 基线管理

- `POST /api/baseline`
  - 入参：task_id（从某次评测创建基线）
  - 出参：baseline_id
- `GET /api/baseline`：查询基线列表

### 回归门禁

- `POST /api/eval/gate`
  - 入参：task_id、baseline_id、阈值配置
  - 出参：通过/失败、变化详情
  - HTTP 状态码：通过 200，失败 422
- **命令行工具**：`java -jar evallab-cli.jar --task <task_id>`
  - 退出码：0（通过）/ 1（失败）
  - 输出：变化详情（JSON 或表格）

### 人工抽检

- `POST /api/manual-review`
  - 入参：result_id、人工评分、人工失败分层、评语
  - 出参：review_id
- `GET /api/manual-review/accuracy`
  - 出参：Judge 准确率、归因准确率

### 红队用例（加分项）

- `GET /api/redteam`：查询红队用例
- `POST /api/redteam`：创建红队用例
- `GET /api/eval/task/{id}/redteam-report`：红队拦截率统计

## 8. 评分器设计

### 规则评分器

- **精确匹配**：输出与期望完全一致，分数 1.0 / 0.0
- **正则匹配**：输出匹配正则表达式，分数 1.0 / 0.0
- **JSON Schema 校验**：输出符合 Schema，分数 1.0 / 0.0

### 工具调用评分器

- **对比逻辑**：提取 Trace 中所有 span 的 tool_name，与用例的 expected_tools 对比
- **评分规则**：
  - 完全匹配（顺序一致）：1.0
  - 工具集合一致但顺序不同：0.8
  - 缺少工具或多调用工具：按比例扣分
- **归因依据**：分数 < 0.5 时归为"工具调用错误"

### LLM-as-Judge 评分器

- **实现**：Spring AI ChatClient，base_url 可配置
- **输入**：用例输入 + 期望输出 + 实际 Trace 输出
- **Prompt 模板**：
  ```
  你是一个评测专家。请评价 Agent 的输出质量（0-1 分）。
  
  任务输入：{input}
  期望输出：{expected_output}
  实际输出：{actual_output}
  
  请返回 JSON：
  {
    "score": 0.85,
    "reason": "输出基本正确，但..."
  }
  ```
- **评分维度**：相关性、正确性、完整性
- **校准**：人工抽检计算准确率（分数差 < 0.1 视为一致）

## 9. 失败归因分层

### 5 层归因规则

1. **输入理解错误**
   - 特征：Agent 未正确解析用户指令
   - 检测：第一个 LLM_CALL span 的输出与输入语义偏差大
   - 示例：用户说"计算 3+5"，Agent 理解成"查询天气"

2. **规划错误**
   - 特征：步骤遗漏或顺序错误
   - 检测：span 数量明显少于预期，或关键工具缺失
   - 示例：多步计算任务只执行了一步

3. **工具调用错误**
   - 特征：工具参数错误或 API 调用失败
   - 检测：span.error 非空，或工具调用评分 < 0.5
   - 示例：HTTP 500、参数类型错误

4. **输出生成错误**
   - 特征：格式错误或内容不完整
   - 检测：输出不符合 JSON Schema，或明显截断
   - 示例：返回 `{"result":` 未闭合

5. **数据/环境问题**
   - 特征：依赖服务不可用、数据缺失
   - 检测：span 中包含"timeout"、"connection refused"等关键词
   - 示例：数据库连接失败

### 归因优先级

按顺序检查，匹配第一个即停止：
1. 数据/环境问题（最底层）
2. 工具调用错误
3. 输入理解错误
4. 规划错误
5. 输出生成错误
6. 未分类（UNKNOWN）

## 10. 回归门禁设计

### 对比指标

1. **通过率**：`passed_cases / total_cases`
2. **平均分**：所有评分的均值（0-1）
3. **P95 耗时**：排序后第 95 百分位的 duration_ms

### 阈值配置

```json
{
  "pass_rate_threshold": -0.10,     // 通过率下降超过 10% 拦截
  "avg_score_threshold": -0.15,     // 平均分下降超过 0.15 拦截
  "p95_duration_threshold": 1.5     // P95 耗时增加 50% 拦截
}
```

### HTTP 接口

**请求**：`POST /api/eval/gate`
```json
{
  "task_id": "current-task-uuid",
  "baseline_id": "baseline-uuid",
  "thresholds": { ... }
}
```

**响应（通过）**：HTTP 200
```json
{
  "passed": true,
  "changes": {
    "pass_rate": "+0.02",
    "avg_score": "+0.05",
    "p95_duration_ms": "-120"
  }
}
```

**响应（失败）**：HTTP 422
```json
{
  "passed": false,
  "reason": "通过率下降 15%（0.85 -> 0.70），超过阈值 10%",
  "changes": { ... }
}
```

### 命令行工具

```bash
java -jar evallab-cli.jar \
  --task current-task-uuid \
  --baseline baseline-uuid \
  --threshold-pass-rate -0.10
```

**退出码**：
- 0：通过
- 1：失败（指标退化）
- 2：参数错误或任务不存在

**输出**：
```
❌ 回归检测失败

通过率：0.85 -> 0.70 (-15%)  [阈值: -10%]
平均分：0.88 -> 0.82 (-0.06)  [阈值: -0.15]
P95 耗时：1200ms -> 1350ms (+12.5%)  [阈值: +50%]

详情：https://evallab.local/report/current-task-uuid
```

## 11. 简历指标体系

| 指标 | 定义 | 采集方式 | 目标值 |
|------|------|----------|--------|
| **归因准确率** | 系统归因与人工标注一致的比例 | `COUNT(system_failure_category = human_failure_category) / COUNT(*) FROM eval_manual_review` | > 80% |
| **Judge 准确率** | Judge 与人工评分一致的比例（差值 < 0.1） | `COUNT(ABS(human_score - judge_score) < 0.1) / COUNT(*) FROM eval_manual_review` | > 75% |
| **回归检出率** | 故意注入的退化被拦截的次数 | 手动注入 3 次退化，记录 `is_regression_detected = true` 的任务数 | 3/3 (100%) |
| **单次评测耗时** | 10 个用例的评测任务完成时间 | `AVG(TIMESTAMPDIFF(SECOND, created_at, completed_at)) FROM eval_task WHERE total_cases = 10` | < 5 分钟 |
| **接入 Agent 数** | 平台已接入的 Agent 数量 | 手动统计 | ≥ 3 |
| **红队拦截率** | 红队用例中 Agent 防御成功的比例 | `COUNT(status = 'PASS') / COUNT(*) WHERE testcase_id IN (SELECT case_id FROM eval_redteam_case)` | > 60% |

**最终以实测值为准，不预设具体数字**
